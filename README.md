## Назначение

Приложение предназначено для централизованного управления
уведомлениями пользователей: регистрации уведомлений, выбора канала
доставки (email, SMS, push), проверки правил отправки и отслеживания
статуса каждого уведомления.

Сервис решает задачу разрозненной рассылки: вместо того чтобы каждая
подсистема отправляла сообщения самостоятельно, все уведомления
проходят через единую точку, где учитываются подписки пользователя,
суточные лимиты каналов, приоритет сообщения и «тихие часы».

## Целевая аудитория

- **Конечные пользователи** — получают уведомления и настраивают
  каналы, подписки и время, в которое их не следует беспокоить.
- **Операторы и администраторы сервиса** — создают и отправляют
  уведомления, контролируют доставку и разбирают неудачные отправки.
- **Разработчики внешних систем** — интегрируют свои приложения с
  сервисом через API и передают события для рассылки.

## Предметная область

Предметная область — управление уведомлениями информационной системы.
Пользователь подписывается на категории уведомлений и указывает
доступные ему каналы связи. Уведомление создаётся системой или
оператором и ставится в очередь на доставку по одному из каналов.
Перед отправкой проверяются правила: активность пользователя, наличие
подписки, включённость канала, суточный лимит отправок, ограничения
канала по длине текста и «тихие часы». По результатам проверки
уведомление получает статус, который изменяется по мере обработки:
создано → отправлено → доставлено → прочитано, либо отложено или
отклонено.

## Основные сущности

- **Пользователь** — получатель уведомлений: идентификатор, имя,
  контактные данные, признак активности, «тихие часы».
- **Уведомление** — сообщение: тема, текст, приоритет, дата создания,
  дата доставки, получатель, канал.
- **Канал** — способ доставки (email, SMS, push): код, признак
  включения, суточный лимит, ограничение длины сообщения.
- **Статус** — состояние уведомления: создано, отправлено, доставлено,
  прочитано, отложено, отклонено.
- **Подписка** — связь пользователя с категорией уведомлений и каналом
  (планируется на следующих этапах).

## Основные функции

- регистрация пользователей и настройка их каналов связи;
- создание уведомления с указанием темы, текста и приоритета;
- выбор канала доставки и проверка правил отправки;
- контроль суточного лимита отправок по каналу;
- учёт «тихих часов» пользователя и отложенная доставка;
- присвоение и изменение статуса уведомления;
- просмотр истории уведомлений пользователя;
- отчёт по доставленным, отложенным и отклонённым уведомлениям.

## Реализовано на ПР1

Начальный сценарий `main.py` — проверка возможности доставки одного
уведомления и определение его статуса. Использованы простые типы
данных, операции, преобразование типов, ветвления (`if-elif-else`),
составные условия, логические операторы и импорт модуля `datetime`.

Правила доставки вынесены в отдельные функции:

- `is_quiet_time()` — попадает ли время в «тихие часы» пользователя;
- `is_too_long_for_channel()` — превышает ли текст лимит длины канала;
- `get_block_reason()` — причина отказа в доставке (или пустая строка);
- `get_status()` — статус уведомления по результатам проверок;
- `get_status_comment()` — пояснение к статусу;
- `get_delivery_time()` — время доставки с учетом «тихих часов».

Запуск:

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
python main.py
```
