# Сервис управления уведомлениями

Консольное приложение для централизованного управления уведомлениями:
учёт пользователей и каналов доставки, проверка правил отправки,
создание и отмена уведомлений, поиск и статистика по статусам.
Начиная с ПР3 приложение построено на объектной модели: сущности
предметной области реализованы классами.

Индивидуальный сквозной проект по дисциплине «Технологии разработки
приложений на базе фреймворков».

## Назначение

Приложение предназначено для централизованного управления
уведомлениями пользователей: регистрации уведомлений, выбора канала
доставки (email, SMS, push), проверки правил отправки и отслеживания
статуса каждого уведомления.

Сервис решает задачу разрозненной рассылки: вместо того чтобы каждая
подсистема отправляла сообщения самостоятельно, все уведомления
проходят через единую точку, где учитываются подписки пользователя,
суточные лимиты каналов, приоритет сообщения и «тихие часы».

## Целевая аудитория

- **Конечные пользователи** — получают уведомления и настраивают
  каналы, подписки и время, в которое их не следует беспокоить.
- **Операторы и администраторы сервиса** — создают и отправляют
  уведомления, контролируют доставку и разбирают неудачные отправки.
- **Разработчики внешних систем** — интегрируют свои приложения с
  сервисом через API и передают события для рассылки.

## Предметная область

Предметная область — управление уведомлениями информационной системы.
Пользователь подписывается на рассылку и указывает контакт: адрес
почты или номер телефона. Уведомление создаётся системой или
оператором и ставится в очередь на доставку по одному из каналов.
Перед отправкой проверяются правила: активность пользователя, наличие
подписки, включённость канала, соответствие контакта каналу, суточный
лимит отправок, ограничение длины текста и «тихие часы». По результатам
проверки уведомление получает статус: отправлено, отложено или
отклонено.

## Основные сущности

- **Пользователь** (`User`) — получатель уведомлений: идентификатор,
  имя, контакт, признак активности, подписка, «тихие часы».
- **Канал доставки** (`Channel`) — абстрактный класс с наследниками
  `EmailChannel`, `SmsChannel`, `PushChannel`: код, название, признак
  включения, суточный лимит, счётчик отправок, ограничение длины.
- **Уведомление** (`Notification`) — тема, текст, приоритет, даты
  создания и доставки, получатель, канал, статус и комментарий.
- **Результат проверки доставки** (`DeliveryResult`) — неизменяемый
  класс данных: статус, комментарий, признак «тихого времени», время
  доставки.
- **Статус** — состояние уведомления: `ОТПРАВЛЕНО`, `ОТЛОЖЕНО`,
  `ОТКЛОНЕНО`.

## Возможности

- просмотр пользователей, каналов доставки и уведомлений;
- проверка возможности отправки по правилам доставки (сценарий ПР1)
  с предпросмотром сообщения в выбранном канале;
- создание уведомления с автоматическим определением статуса;
- отмена уведомления, кроме уже отправленного;
- поиск уведомлений по подстроке темы или текста;
- статистика по статусам с долей каждого статуса;
- добавление пользователя и изменение его подписки;
- справка о классах проекта средствами интроспекции;
- контроль суточных лимитов каналов, длины SMS и соответствия
  контакта каналу;
- учёт «тихих часов» пользователя и расчёт отложенной доставки.

## Объектная модель (ПР3)

```
Entity (ABC)
├── User
├── Channel (ABC)
│   ├── EmailChannel
│   ├── SmsChannel
│   └── PushChannel
└── Notification

Repository ──┬── UserRepository         (+ AutoIdMixin)
             ├── ChannelRepository
             └── NotificationRepository (+ AutoIdMixin)

NotificationService ── users, channels, notifications, DeliveryRules
ConsoleApp ── NotificationService
```

- **Инкапсуляция.** Данные объектов хранятся в защищённых атрибутах
  (`_id`, `_subscribed`, `_sent_today`, `_status`), доступ к ним — через
  свойства `@property`. Идентификаторы, статус и счётчик отправок
  доступны только для чтения, имя, контакт, «тихие часы», лимит и
  приоритет проверяются в сеттерах. Подписка и активность меняются
  методами `subscribe()`, `unsubscribe()`, `activate()`, `deactivate()`.
- **Наследование.** Все сущности наследуют абстрактный класс `Entity`
  с общим интерфейсом `key`, `to_dict()`, `from_dict()` и сравнением
  по ключу. Каналы `EmailChannel`, `SmsChannel`, `PushChannel`
  наследуют общую логику лимитов от `Channel`. Хранилища наследуют
  `Repository`, а `UserRepository` и `NotificationRepository`
  дополнительно получают метод `next_id()` от примеси `AutoIdMixin`
  (множественное наследование).
- **Полиморфизм.** Каждый канал по-своему реализует методы
  `accepts_contact()` (почта — адрес с `@`, SMS — номер телефона,
  push — любой контакт) и `format_message()` (письмо с темой, SMS без
  темы, push одной строкой). Правила доставки и консольный интерфейс
  вызывают эти методы, не зная конкретного класса канала. Фабричный
  метод `Channel.from_dict()` создаёт объект нужного наследника по коду.
- **Абстракция.** `Entity` и `Channel` — абстрактные классы (`abc`),
  создать их объекты нельзя.
- **Магические методы.** `__str__`, `__repr__`, `__eq__`, `__hash__`
  у сущностей; `__lt__` у уведомления (сортировка `sorted()`: сначала
  срочные, затем по дате); `__len__`, `__iter__`, `__contains__` у
  хранилищ.
- **Декораторы.** Встроенные `@property`, `@staticmethod`,
  `@classmethod`, `@abstractmethod`, `@dataclass` и собственный
  декоратор с параметром `@menu_action("ЗАГОЛОВОК")`, который выводит
  заголовок пункта меню и перехватывает ошибки предметной области.

Начальный сценарий ПР1 сохранён: правила проверки доставки стали
методами класса `DeliveryRules` (`block_reason`, `status`, `comment`,
`delivery_time`, `check`), сценарий доступен пунктом меню 4.

## Формат хранения данных

Данные хранятся в JSON-файлах каталога `data/` — списками словарей;
формат не изменился с ПР2. При загрузке словари превращаются в объекты
методами `from_dict()`, при сохранении — обратно методами `to_dict()`.
Чтение и запись выполняет класс `JsonStorage` через контекстный
менеджер `with`; отсутствие файла, некорректный JSON и некорректные
записи не прерывают работу программы.

```json
[
  {
    "id": 1,
    "user_id": 1,
    "channel": "email",
    "subject": "Плановые технические работы",
    "text": "Сервис будет недоступен 12.09.2026 с 02:00 до 04:00.",
    "priority": 2,
    "created_at": "10.09.2026 23:40",
    "status": "ОТЛОЖЕНО",
    "comment": "Отправка запрещена в «тихие часы» пользователя",
    "delivery_at": "11.09.2026 08:00"
  }
]
```
